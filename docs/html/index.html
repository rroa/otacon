What Otacon is

Otacon is a small 2D game engine, built as a static library (src/engine/, namespace otacon). It is deliberately game-agnostic: three games ship in this repo — src/game/canabalt/, src/game/dino/ (the Chromium T-Rex runner) and src/game/flappy/ — and each links the same unchanged library, talking to it only through public interfaces. They differ in logical resolution (480×320 / 600×150 / 288×512), camera model and level design; a fourth would be one more IGame and one more CMake target.

Golden rule: engine code never mentions the game, and game code never mentions GLFW / OpenGL / Vulkan / CoreAudio. Everything crosses through four seams: IGame, IWindow, IRenderer, IAudio.

Philosophy

  • In-house subsystems. Math (with a fixed-point scalar), vectors, a memory manager, time, a debug runtime, the OpenGL loader, and even the PNG and CAF asset decoders are written from scratch. The only third-party code is the window library, fetched automatically.
  • Pluggable backends. Graphics (legacy/modern OpenGL, Vulkan) and window (GLFW, SDL2) are chosen by one config flag, selected at compile time.
  • Verifiable. Every renderer is held to a byte-identical contract (proven by SHA-256).

Building & configuration

The engine is the otacon static-library target, built as part of the CMake project. A game executable links it.

cmake -S . -B build          # first configure fetches the window library
cmake --build build -j8      # builds libotacon.a + the game exes

Compile-time choices live in config/build.cfg (or override with -D):

The four seams

IGame — the game contract

A game is one object implementing IGame; the engine's App owns the window, renderer, audio, timing and debug runtime and drives it.

struct GameContext { IRenderer* renderer; IWindow* window; IAudio* audio;
                     DebugRuntime* debug; int logicalW, logicalH; const char* assetDir; };
class IGame {
    virtual void init(GameContext&) = 0;
    virtual void handleInput(const InputFrame&) = 0;
    virtual void update(Real dt) = 0;
    virtual void render(IRenderer&, const DebugRuntime&) = 0;
    virtual void shutdown() {}
};

IWindow — window, input, context

createWindow(cfg) returns the compiled-in backend (GLFW or SDL2). It exposes a uniform InputFrame (edge + held arrays keyed by an Action enum, mouse, drag button), the GL context plumbing, and the Vulkan surface plumbing. Both backends are complete and interchangeable.

IRenderer — drawing

A backend implements only triangle submission + frame lifecycle; all shapes are tessellated once in the shared base, so every backend draws identical geometry. See the drawing API.

IAudio — sound

createAudio() returns the platform device (CoreAudio on macOS, silent stub elsewhere); never null. The game uploads decoded PCM with createSound, then fires play / playMusic. See Audio.

Writing a game

A minimal game draws something each frame:

class MyGame : public otacon::IGame {
    otacon::IRenderer* r_ = nullptr;
    void init(otacon::GameContext& ctx) override { r_ = ctx.renderer; }
    void update(otacon::Real dt) override { /* advance simulation */ }
    void render(otacon::IRenderer& r, const otacon::DebugRuntime&) override {
        r.fillRect(100, 100, 64, 64, otacon::Color::rgb(0xf0c020));
    }
    const char* title() const override { return "My Game"; }
};
// main(): otacon::App app; MyGame game; if (app.init(cfg,&game,dir)) app.run();

The drawing API

The renderer works in a fixed logical space (480×320, origin top-left, y down); each backend applies its own projection. Colours are straight-alpha RGBA.

CallDraws
fillRect(x,y,w,h,color)a filled rectangle
fillRotatedRect(cx,cy,w,h,deg,color)a rectangle rotated about its centre
drawRectOutline(x,y,w,h,color,t)a rectangle outline
drawLine(x0,y0,x1,y1,color,t)a thick line segment
drawImage(tex,x,y,w,h,u0,v0,u1,v1,tint)a texture sub-rect into a dest rect
drawImageRotated(tex,cx,cy,w,h,deg,…)a rotated textured quad
drawText(text,x,y,scale,color)a string in the built-in 3×5 bitmap font

Textures come from a decoded Image via createTexture(img, repeat) (nearest filtering), and updateTexture(tex, w, h, rgba) replaces an existing texture’s pixels at the same extent — the upload path for anything rasterised on the CPU each frame.

The contract: a backend implements only submitTriangles / submitTextured, the texture entry points, and beginFrame/endFrame; every primitive is tessellated to triangles once in the base class, so all backends rasterise identical geometry. Anything beyond that is an optional capability a backend may decline — see Samples.

The scene system

A small scene graph keeps rendering in one place — the Scene renders the tree, nothing draws on the side.

  • Entity — simulation/collision data (pos, size, velocity, the solid/fixed/moves flags, a scrollFactor for parallax, optional texture/colour). updateMotion integrates it.
  • Node — a scene-tree element with update/render (emitters, sprite drawers, facade renderers, UI); may override renderColliders.
  • Scene — owns the camera, an ordered entity draw layer, a backdrop node list (drawn before the entities, for the farthest parallax) and the main node list (after).
  • Camera — a faithful flixel follow camera (centre, lerp, clamp) projecting world→screen through each entity's scrollFactor; hosts the screen-quake.
  • Collision — flixel's swept-AABB separation (solveX then solveY).
  • Emitter — a pooled particle emitter (burst/continuous, gravity/drag/spin, optional sprite sheet).

Core subsystems

Math & the pluggable scalar

Real is the engine number type: an IEEE float by default (bit-for-bit reproducible), or an in-house Q16.16 Fixed with SCALAR_TYPE=FIXED — a determinism/range teaching point (it saturates near ±32768). Vectors are templated on the scalar.

Memory

Three classic allocators: a tracked heap (per-block tags + leak report), a linear Arena (bump, reset per frame), and a fixed-size Pool (free-list, O(1)). Global new/delete are intentionally not overridden.

Time

TimeManager produces the per-frame dt: a variable step (flixel-exact, clamped to 1/20 s) or a fixed step (frame-rate-independent). It also drives the slow-mo/fast-forward time scale.

Debug runtime

DebugRuntime holds toggleable views (colliders, focus, parallax, grid, wireframe, velocities, HUD), pause/step and presets — plain state read each frame, so every backend gets identical visualisation. A single "UI hidden" flag gives clean play (and is what --capture uses).

In-house asset decoders

PNG (asset/Png.cpp, Inflate.cpp): a from-scratch DEFLATE/zlib inflater + a PNG chunk parser that undoes the scanline filters and expands grayscale / RGB / palette+tRNS / RGBA to RGBA8. A matching encoder (PngWrite.cpp) writes screenshots via stored DEFLATE blocks — no compressor needed.

CAF audio (asset/Caf.cpp): parses the Core Audio Format container and decodes LPCM (any width/endianness) to interleaved float as an AudioClip.

Audio

The IAudio device owns an in-house software Mixer (a pool of one-shot voices + one looping music voice, summed into stereo float with gain + soft-clamp; resampled on upload) and a thin platform output. The CoreAudio backend drives a DefaultOutput AudioUnit whose render callback pulls from the mixer; the null backend stays silent. A short mutex bridges the game and audio threads.

Graphics backends

Every backend honours the same contract: logical 480×320 (origin top-left, y down), straight-alpha blending, triangle lists only.

  • GL Legacy (2.1) — glOrtho + immediate mode; compatibility context, no loader. Fixed-function throughout, so there is no programmable stage and supportsShaders() is false.
  • GL Modern (core 3.3) — streamed VBO/VAO + a small shader pair; needs a function loader, shipped in-house (gl_modern/GLLoader, no GLAD/GLEW). The only backend with a reachable programmable stage, so the one where supportsShaders() is true.
  • Vulkan — full instance/device/swapchain/pipelines from embedded SPIR-V; the shader does not flip y (Vulkan clip space is already y-down). Shaders are pre-compiled to SPIR-V and embedded at build time, so there is no runtime compiler and supportsShaders() is false; updateTexture works, via a staging buffer per upload. Validation-clean; on macOS uses MoltenVK via tools/run.sh <target>.

Samples

Fifteen sample screens (src/samples/, executable samples) exercise the engine on its own. They link otacon and nothing else, and generate every texture they use in code — a sample that borrowed a game’s art would mean a seam had leaked. One gallery object hosts them all, so adding a sample is one .cpp plus one row in Registry.cpp.

Run: ./build/bin/samples (F1 for the list), or --sample N to open one directly. On the Vulkan backend use ./tools/run.sh samples.

Per-pixel work and the shader seam

Two samples — 2D lighting, and the shader playground — need per-fragment control, which sits awkwardly against the cross-backend contract: only GL modern has a reachable programmable stage. The engine therefore offers both halves and lets a sample choose.

  • updateTexture(tex, w, h, rgba) re-uploads an existing texture’s pixels. A sample shades a buffer in plain C++ and pushes it once per frame. Works on every backend, GL legacy included.
  • createEffect(fragmentSrc, log, logSize) compiles a user fragment shader, with useEffect and setEffectUniform to drive it. The engine keeps the vertex stage, so the projection is unchanged and a user shader cannot move geometry out from under the contract. supportsShaders() reports whether the backend can do this at all.

Every sample that uses an effect also carries the CPU path, so no sample is backend-exclusive and the cross-backend contract still holds everywhere.

Verification

tools/backend-diff.sh renders the same deterministic frame in each graphics backend and compares the PNGs. Across both window backends, the full matrix — {GLFW, SDL2} × {GL_MODERN, GL_LEGACY, VULKAN} — yields the same SHA-256 in all six combinations: proof that neither seam perturbs a single pixel. The headless otacon_smoke target additionally unit-tests the integrator, collision, the emitter, fixed-point math, the PNG/CAF decoders and the audio mixer.
